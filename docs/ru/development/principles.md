# Принципы разработки

Ключевые концепции и принципы Syncle. Документ отвечает на вопросы
«зачем устроено так» и «как принимать решения»; проверяемые правила —
в [standards.md](standards.md), реализация принципов — в
[patterns.md](patterns.md).

## Архитектурные концепции

### Слоистая архитектура

```
интерфейсы (bot, worker, api)  →  модули (домен)  →  core (инфраструктура)
```

- **Модули** (`src/modules/*`) — доменная логика: аналитика, SEO,
  юридический сканер, финансы и т.д. Это сердце продукта.
- **Core** (`src/core/*`) — инфраструктура, не знающая о домене:
  Redis, HTTP, LLM, задачи, документы, БД.
- **Интерфейсы** — точки входа, адаптирующие внешний мир к домену:
  - **бот** (aiogram) — первичный интерфейс продукта;
  - **worker** (Taskiq) — исполнение фоновых задач;
  - **api** (HTTP) — заготовка под будущий интерфейс.

Домен не знает, кто его вызывает. Поэтому новый интерфейс (тот же
api) подключается добавлением адаптера, а не правкой модулей.

### Модульность и владение

Модуль — граница ответственности. Каждый модуль самодостаточен:

- свои схемы (`schemas.py`), ошибки (`errors.py`), тарифы/константы;
- публичный сервис (`service.py`) — единственный канал для соседей;
- свои фоновые задачи (`jobs.py`) при необходимости.

Правило «работаешь в своём модуле»: изменения фичи живут внутри модуля
и его адаптера в боте; выход за границы (правка соседнего модуля,
core) — сигнал, что нужна отдельная договорённость, а не «быстрый
фикс». Кросс-модульное взаимодействие идёт только через публичные
сервисы и схемы, никогда — через внутренние файлы.

## Принципы

### SOLID

- **S — единственная ответственность.** Модуль делает одну доменную
  вещь (финансы ≠ репутация ≠ право). Файл в модуле — тоже одна
  причина к изменению: парсер, детектор, калькулятор разнесены.
- **O — открыт/закрыт.** Новое поведение — новая реализация за портом,
  а не правка существующей. Пример: `JobRunner` не менялся при
  добавлении Taskiq — появился `TaskiqJobRunner`.
- **L — подстановка.** Реализации портов взаимозаменяемы:
  `InlineJobRunner` и `TaskiqJobRunner` обещают один контракт
  `submit/status/wait` — сцены бота не различают их.
- **I — сегрегация.** Порты узкие: `DocumentParser` умеет только
  «байты → текст/строки», а не «всё про документы».
- **D — инверсия зависимостей.** Зависимость направлена от домена к
  абстракции: модуль импортирует протокол из core, адаптер подставляет
  реализацию. Проверяемый признак — `core` никогда не импортирует
  модули; модули не импортируют aiogram.

### DRY

Общее живёт один раз и в правильном слое:

- общий парсер документов, HTTP-клиенты, LLM-шлюз, фреймворк задач —
  core, а не копии в модулях;
- дубль в двух модулях — сигнал вынести в core или в общий модуль;
- но DRY не означает раннюю абстракцию: два похожих случая — не
  повод для базового класса (см. YAGNI).

### KISS

Простейшее решение, которое покрывает реальную потребность:

- фоновая задача = лёгкий JSON-payload, тяжёлое — в stash;
  никаких «универсальных» контейнеров состояния;
- бот-сцена — линейный сценарий (запрос → шаг → результат), не
  конечный автомат на все случаи жизни;
- схемы — плоские pydantic-модели без наследования ради наследования.

### YAGNI

Не реализовываем то, что не нужно сегодня. Заготовки делаются ровно
в размер будущего, а не «на вырост»:

- `src/api/` — пустой слой точки входа, чтобы не переписывать слои;
- HTTP-профиль `ozon` — URL распознаётся, парсер бросает
  `UnsupportedMarketplaceError`;
- Ozon-тарифы в finance — таблицы заполнены, калькулятор уже умеет
  сегменты, но полноценный ozon-парсер отчётов не пишем, пока нет
  выгрузок.

Признак нарушения: «класс/абстракция для будущих трёх случаев» при
одном реальном.

## Как это ощущается в работе

1. Пришлил задачу → определи модуль-владелец (часто один).
2. Код фичи — модуль + тонкий адаптер в боте (тексты/клавиатуры).
3. Нужен общий кусок → сначала уточни, не core ли это (третье правило
   констант, порт вместо копипасты).
4. Сомневаешься между решениями — выбирай то, которое проще закрыть
   и сложнее злоупотребить (KISS + YAGNI), оставляя расширение за
   портом (SOLID).
