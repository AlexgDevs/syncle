# Стандарты разработки

Единые правила кодирования, проверки и сдачи работ для Syncle.
Концепции и принципы, на которых стоят эти правила, — в
[principles.md](principles.md). Дополняется по мере появления новых
договорённостей.

## Языки

| Где | Язык |
|---|---|
| Код модулей (`src/modules/`, `src/core/`), docstring, имена | EN |
| Промпты LLM, коды прогресс-степов (`PROGRESS_STEPS`) | EN |
| Тексты бота, reply/алерты, рендеры отчётов (`src/bot/`) | RU |
| Пользовательский контент модулей (RU-описания сборов, алерты) | RU |
| Документация (`docs/`), ADR | RU (EN — перевод) |

Комментарии в коде — EN. Исключение из правила языка — user-facing
контент: он RU независимо от места в файле (прецедент:
`modules/finance/tariffs.py` хранит RU-описания скрытых сборов).

## Слои и зависимости

```
bot / worker / api  →  modules  →  core
```

- `core` не импортирует `modules` и точки входа. Проверка:
  `grep -r "from src.modules" src/core` — пусто.
- `modules` не импортируют aiogram и не содержат Telegram-типов.
  Проверка: `grep -r "aiogram" src/modules` — пусто.
- Бизнес-логика живёт в модуле; интерфейсы (бот, worker, api) —
  тонкие адаптеры без доменных решений.

## Стиль кода

- Форматирование и типизация — `black` и `mypy` из `backend/`:
  `uv run black src && uv run mypy src`. Оба зелёные — DoD.
- Python 3.14, зависимости через `uv`.
- Pydantic v2: схемы домена — в `schemas.py` модуля; `Decimal` для
  всех денег и процентов (никогда `float`).
- Фабрики синглтонов — `@lru_cache def get_x_service()` (наследие
  pydantic-settings `get_settings()`).
- Константы: приватная `_CONST` модуля → `constants.py` пакета при
  потребности 2+ модулей → `core/settings.py`, если меняется при
  деплое (подробнее — patterns.md).
- Нейминг: `SCREAMING_SNAKE` для констант, `_`-префикс для приватного.

## Работа с файлами

- Правки кода — через инструменты редактирования (edit/write) или
  `git checkout` + повторный патч. **Не** использовать командлеты
  PowerShell (`Set-Content`/`Add-Content`) для файлов с RU/эмодзи —
  PS 5.1 перезаписывает их в ANSI (см. lessons.md).
- Контроль целостности после правок в `src/` — поиск байтов
  `EF BF BD` (replacement char): 0 совпадений.

## Коммиты и ветки

- Формат: `feat|fix|chore(<scope>): краткое описание #NN` — номер
  issue в заголовке.
- Коммит — логическая единица (модуль или слой); смешение несвязанных
  правок запрещено.
- Ветка фичи — от `dev`: `alexgdev-<тема>`. Stacked PR допустим:
  ветка A над веткой B, PR-ы в определённом порядке.
- Тело PR: `Closes #NN`, секции What / Verification (по образцу #72, #73).
- Коммит/пуш/PR — только по явной команде владельца.

## Definition of Done

1. `uv run black src` + `uv run mypy src` — чисто.
2. Смоук-скрипт нетривиальной логики (во временной папке, не в git)
   с реальными фикстурами из `backend/tests/fixtures/`.
3. Живой прогон бота (рестарт + ручная проверка сцены).
4. Пользовательский слой (тексты/клавиатуры адаптера) обновлён вместе
   с логикой; заглушек в проде быть не должно.
5. Docstring модуля отражает контракт (капы, guard'ы, error-пути).

## Ревью-чек-лист

- Импорты не нарушают направление слоёв.
- Нет `float` для денег; деньги — `Decimal`.
- Нет aiogram в модулях; нет строк RU в модулях без user-facing роли.
- Все новые Redis-ключи имеют TTL; байтовые капы на всё, что пишется
  в stash.
- Ошибки домена — через `SyncleError`-дерево; RU-текст для
  пользователя маппится в `bot/errors.py`.
- Лимиты интерфейса соблюдены (капы сообщений/клавиатур — см.
  lessons.md).

## Что не делаем

- Юнит-тесты в репозитории (не приняты на текущем этапе; вместо них —
  смоуки и фикстуры).
- Миграции и переписывание смержённого без обсуждения.
- Секреты в git: `.env` не коммитится; локальный `ARCHITECTURE.md` —
  через `.git/info/exclude`.
