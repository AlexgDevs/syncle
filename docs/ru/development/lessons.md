# Практические выводы

Правила, проверенные на реальных ошибках проекта. Краткие выводы без
историй инцидентов; контекст и «почему так» — при написании документации
соответствующего модуля (`docs/*/modules/`).

## Файлы и кодировка

- Не использовать командлеты PowerShell (`Set-Content`/`Add-Content`)
  для файлов с RU/эмодзи: PS 5.1 перезаписывает их в ANSI. Правки —
  через инструменты редактирования или `git checkout` + повторный патч.
- После правок в `src/` — контроль: поиск байтов `EF BF BD`
  (replacement char), должен быть 0.

## Деньги

- Только `Decimal`, никогда `float`: сравнение
  `Decimal("1.10") == 1.10` — `False`. Литералы в сравнениях тоже
  `Decimal(...)`.

## Данные и хранение

- Реальные файлы (XLSX/CSV) не похожи на синтетические: мультитаб,
  сводные блоки сверху, листы-соседи. Фикстуры реальных выгрузок —
  в `backend/tests/fixtures/`; каждый парсер верифицируется на них.
- Redis: TTL обязателен для всего, что пишется (stash, job-ключи,
  служебные SET); байтовые капы — на всё приходящее от пользователя.
  `maxmemory` + `volatile-ttl` (config/redis.conf) страхуют от OOM.
- Job-only stash-ключи не пишутся в inline-режиме — иначе мёртвые
  блобы.

## Интерфейс

- Лимиты Telegram: `copy_text` ≤ 256 символов; клавиатура ~10 KB /
  100 кнопок (пагинация); подписи к медиа ≤ 1024 символов.

## Процесс

- Stacked PR: ветка над веткой, тело PR — «Stacked on #NN — merge that
  one first»; после мержа нижнего PR верхний сжимается автоматически.
- Смоуки вместо юнит-тестов: скрипт во временной папке
  (`PYTHONIOENCODING='utf-8'`, `PYTHONPATH='.'`, запуск из `backend/`
  через `uv run python`), happy path + error-пути + регрессии на
  фикстурах.
